# Cordon for Gmail (Google Workspace add-on)

A thin Gmail sidebar client. Open an email with the Cordon panel open and it is analyzed
automatically: the add-on sends the raw message to Cordon's `POST /v1/analyze/email` and shows
the result: verdict, score, a one-line summary, the top
indicators, SPF/DKIM/DMARC, and the compliance-framework tags. All detection runs in the
Cordon backend, the same pipeline as the web app's Analyze page. The add-on renders only what
the API returns.

These files don't run from this repo. You copy them into a Google Apps Script project.

| File | What it is |
| --- | --- |
| `appsscript.json` | Manifest: Gmail contextual trigger, OAuth scopes, URL allowlist |
| `Code.gs` | The add-on: reads the open message, calls Cordon, renders cards |

## 1. Get a Cordon API key

1. Sign in at <https://app.cordoncybersec.us>.
2. Go to **Settings → API keys**, name the key (e.g. "Gmail add-on"), and click **Create key**.
3. Copy the key. It starts with `cdn_`, and **it is shown only once**. Cordon stores only a
   hash. If you lose it, revoke it and create a new one.

The key analyzes email as you. Once it is saved, each email you open with the Cordon panel
showing is sent to Cordon and analyzed. Only **suspicious or malicious** results are saved as
Cases in your Cordon account (the add-on sends `"persist": "if_not_clean"`); clean mail is
analyzed, shown, and not saved. Analyzing an already-saved email again reuses its Case
instead of creating a new one.

Results are cached per message for 6 hours (Apps Script `CacheService`, per user), so
re-opening an email doesn't call Cordon again or count against the rate limit. **Re-analyze**
on any result card always makes a fresh call.

## 2. Create the Apps Script project

1. Go to <https://script.google.com> and click **New project**. Name it "Cordon for Gmail".
2. Click **Project Settings** (gear icon) and tick **Show "appsscript.json" manifest file in
   editor**.
3. Back in **Editor**:
   - Open `appsscript.json` and replace its contents with this folder's `appsscript.json`.
   - Open `Code.gs` and replace its contents with this folder's `Code.gs`.
4. Save the project (Ctrl/Cmd+S).

If your Cordon backend is not the production one (`https://aegis-backend-zbcr.onrender.com`),
change it in **both** places, or Google blocks the request:
- `CORDON_API_BASE` at the top of `Code.gs`
- `urlFetchWhitelist` in `appsscript.json` (keep the trailing `/`)

## 3. Install it for yourself (test deployment)

1. Click **Deploy → Test deployments**.
2. Under **Application(s): Gmail**, click **Install**, then **Done**.
3. Open Gmail (refresh if it was already open) and open any email. The Cordon icon appears in
   the right-hand side panel. Click it.
4. The first time, Google asks you to authorize the add-on. It requests three scopes:
   - read the **currently open** message only (`gmail.addons.current.message.readonly`), not
     your whole mailbox;
   - run as a Gmail add-on (`gmail.addons.execute`);
   - call an external service, Cordon (`script.external_request`).

   For an unpublished test deployment Google shows an "unverified app" screen. That is expected
   for your own script. Choose **Advanced → Go to Cordon for Gmail (unsafe)**.

## 4. Paste your API key

On first open the add-on shows a **Cordon settings** card:

1. Paste the `cdn_…` key into **Cordon API key**.
2. Click **Save**. The open email is analyzed right away.

The key is stored in your Apps Script **user properties** (`PropertiesService.getUserProperties()`).
Only your own runs of the script can read it, and it is never logged. To replace it, click
**API key** at the bottom of any result card, or open the Cordon add-on with no email selected.

## What you'll see

- **Clean mail** gets a compact card: "Clean ✓ · nothing suspicious", the score, SPF/DKIM/DMARC,
  and "Not saved to Cordon."
- **Suspicious / malicious mail**: the full card below, and the email is saved as a Case.
- Every result card has **Re-analyze**, **Open Cordon** and **API key** buttons.

The full card shows:

- **Header and verdict banner**, colored by verdict: red = malicious, amber = suspicious,
  green = clean. Plus the 0–100 risk score.
- **Summary**: one sentence generated by Cordon from the verdict and its findings.
- **Top indicators**: up to three, highest-weighted first.
- **Sender authentication**: SPF / DKIM / DMARC as `pass`, `fail` or `none`, read from the
  receiving server's `Authentication-Results` header.
- **Framework mappings**: MITRE ATT&CK, NIST CSF, ISO 27001 and SOC 2 control tags.

Gmail add-on cards can't color the header bar per card. The add-on's toolbar uses Cordon's
accent color, and the verdict color is applied to the banner line directly under the header.

## First test: confirm the read scope is enough

The add-on reads the message with `GmailMessage.getRawContent()` under only the open-message
scope (`gmail.addons.current.message.readonly`, classified *sensitive*). Google's reference
lists only `https://mail.google.com/` for that method, so whether the narrow scope covers it
must be confirmed on a real email.

After installing, open any email. Automatic analysis keeps failures quiet (a small **Tap to
analyze** card), so if you see that card, tap it to see the detailed error:
- A result card means the narrow scope works.
- **Couldn't read this email** with "Gmail said: …" means it doesn't. Note the exact text, and
  **do not** widen the scope to `gmail.readonly` or `https://mail.google.com/` to fix it: both
  are *restricted* scopes, which require Google's annual security assessment (CASA) to publish.

## Errors

When an email is opened, every failure except a rejected key shows the quiet **Tap to analyze**
card instead of an error, and failures are not cached. Tapping it (or **Re-analyze**) shows the
specific card:

| Card | Meaning |
| --- | --- |
| **Check your Cordon API key** | Cordon returned 401: the key is wrong, was revoked, or its user was deactivated. Paste a new key. |
| **Couldn't read this email** | Gmail refused to hand over the message; Google's own error text is shown. See "First test" above. |
| **Couldn't reach Cordon** | Network failure or an unexpected server response. Use **Try again**. |
| **Slow down a little** | More than 30 analyses per minute with this key. |
| **Email too large** | The message is over Cordon's 10 MiB analysis limit. |

## API contract (for reference)

```
POST https://aegis-backend-zbcr.onrender.com/v1/analyze/email
Authorization: Bearer cdn_...
Content-Type: application/json

{ "raw_email": "<full RFC-822 message>", "persist": "if_not_clean" }
```

`persist` is optional: `"always"` (the default) saves every result as a Case;
`"if_not_clean"` saves only suspicious/malicious results. The response is identical either way.

```json
{
  "verdict": "malicious | suspicious | clean",
  "score": 0,
  "category": "string",
  "summary": "one sentence",
  "top_indicators": ["...", "...", "..."],
  "auth": { "spf": "pass|fail|none", "dkim": "pass|fail|none", "dmarc": "pass|fail|none" },
  "frameworks": ["MITRE T1566", "NIST DE.CM-01", "ISO A.5.7", "SOC 2 CC7.2"]
}
```

## Sharing it with others

A test deployment only installs for you. To roll it out to a Google Workspace domain, link the
script to a Google Cloud project and publish it through the Google Workspace Marketplace SDK
(private, domain-only listing). Each user still pastes their own Cordon API key.
